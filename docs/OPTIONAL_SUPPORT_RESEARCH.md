# Optional support backend: investigation and implementation gate

Reviewed 21 November 2026. This is the original research/design record. The physical-generation prerequisite has since been met, and implementation is documented in [the support service README](../support/README.md). Deployment and acceptance status belong in [the support test report](SUPPORT_TEST_REPORT.md). The proposed limits below are historical; the implementation uses 32 KiB reports, one global two-hour storage slot and private Blob expiration. All inference, checkpoints, prompts, and videos remain local.

## Existing installation path

The bundled schema-1 manifest already pins the MOVD revision, three HTTPS archive URLs, byte counts, SHA-256 digests, and required partition names. The archives total **14,133,836,614 bytes**. `ModelInstaller` saves URLSession resume data, hashes archives with bounded buffers, stages extraction/compilation, and activates the installed model after preparation. The current manifest is bundled, not a remote API, and has no minimum-app-version field. Resume-data support does not prove interoperability with a new host's redirects, range responses, or expired download URLs.

## Vercel Hobby feasibility

Vercel describes Hobby as free for personal, noncommercial use. Its current plan documentation lists 100 GB of Fast Data Transfer, 1 million invocations, 4 CPU-hours, and 360 GB-hours of provisioned memory. Hobby usage is capped; exceeding a limit can pause service rather than purchase extra usage. Confirm the signed-in account is still Hobby before deployment, and enable no paid upgrades, trials, marketplace storage, or metered add-ons. The app must tolerate the backend being unavailable. [Hobby plan](https://vercel.com/docs/plans/hobby), [account plans](https://vercel.com/docs/plans), [pricing](https://vercel.com/pricing).

Use Vercel for small static versioned JSON documents and, only after a viable storage/retention design is established, a bounded diagnostic intake endpoint. Do not proxy the model archives through Vercel. The model is far larger than the documented default function payload limit, and even a hypothetical 100 GB transfer allowance would cover only about seven complete 14.13 GB downloads before other traffic. [Function limits](https://vercel.com/docs/functions/limitations).

Hobby's short runtime-log retention is unsuitable as the sole durable diagnostic store. **Private Vercel Blob is a candidate**: current Hobby allowances are 1 GB-month storage, 2,000 advanced operations, 10,000 simple operations, and 10 GB transfer. Vercel says Hobby overages stop access without charging extra. Private stores require authenticated reads and writes; credentials must stay on the server. An initial budget of at most 500 reports per month, 16 KiB per report, and 30-day retention would use under 8 MiB of payload storage, with operation headroom required for listing, management and cleanup. These are proposed caps, not measured usage. [Blob pricing](https://vercel.com/docs/vercel-blob/usage-and-pricing), [private storage](https://vercel.com/docs/vercel-blob/private-storage).

A future implementation must enforce payload/field limits, provide abuse controls, verify the account's remaining shared quotas, and document retention, access and deletion. Local diagnostics and manual export remain usable during quota exhaustion. No remote diagnostic destination has been provisioned.

## Hugging Face distribution

Public storage for free accounts is **best-effort**, with responsible community reuse expected beyond the first few gigabytes. This is not a guaranteed unlimited distribution service. The current repository guidance recommends individual files under 200 GB, so the three existing archives fit that recommendation; storage acceptance and practical download reliability still require validation. Preserve immutable revision URLs and the existing independently calculated SHA-256 digests. [Storage policy](https://huggingface.co/docs/hub/en/storage-limits).

The documented five-minute resolver allowance is 3,000 requests per anonymous IP and 5,000 for a free authenticated user; free limits can change with platform health. Handle 429 responses and reset/retry information with bounded backoff. Never ship a developer access token inside the iOS app. [Rate limits](https://huggingface.co/docs/hub/rate-limits).

Hugging Face documents bandwidth accounting against a plan's allowance, while its pricing page describes CDN/egress as included. These are not evidence of unlimited free bandwidth, guaranteed throughput, or a universally applicable numeric free egress cap. Check the actual account allowance before publishing and record observed range/resume behavior. A full model installation consumes roughly 14.13 GB of transferred archive bytes, excluding retries. Downloads may redirect to Hugging Face storage/CDN hosts. [Download analytics](https://huggingface.co/docs/hub/en/download-analytics), [pricing](https://huggingface.co/pricing), [download documentation](https://huggingface.co/docs/hub/models-downloading).

Licensing remains a separate publication gate. The OpenSora [STDiT-v3](https://huggingface.co/hpcai-tech/OpenSora-STDiT-v3) and [VAE-v1.2](https://huggingface.co/hpcai-tech/OpenSora-VAE-v1.2) pages identify Apache-2.0. The exporter references [DeepFloyd/t5-v1_1-xxl](https://huggingface.co/DeepFloyd/t5-v1_1-xxl), whose current page has no model card or displayed license. MOVD's MIT source-code license alone does not establish permission to redistribute every exported weight. Trace exact weight/tokenizer revisions and preserve their notices before mirroring the bundle. See [existing provenance notes](THIRD_PARTY_NOTICES.md). No model mirror has been uploaded.

## Proposed implementation after the physical test passes

1. A versioned manifest API adds model version, minimum compatible app version, exact sizes and hashes, immutable URLs, partition inventory, and the validated configuration identifier. A bundled fallback remains available. Validate schema, allowed values, revision, compatibility, URL policy and integrity before accepting remote data.
2. An optional configuration refresh atomically caches only a valid response. Offline startup immediately uses the last valid configuration or bundled defaults, without requiring a network timeout. Configuration advertises validated options; it cannot silently change the reference schedule or invalidate an installed working model.
3. Downloads go directly to the approved distribution host. Test byte-range resume, redirect expiry, interrupted transfer, full-disk, malformed content, wrong length/hash, cancellation and retry. Stage each update separately, keep the installed version usable until verification completes, and retain a rollback option.
4. Diagnostic uploads default off. Show the exact structured report and destination before explicit consent. Use an allowlist of app/model/OS versions, partition identifiers, error categories/codes, durations, memory samples and thermal states. Never upload raw journals, arbitrary error descriptions, prompts or their hashes, tensor contents, file paths, device identifiers, videos or personal files. The server independently rejects unknown fields. Document unavoidable hosting request metadata separately.
5. A local developer screen summarizes partition load/prediction times, failures, memory peaks and generation errors without enabling upload. Existing local video storage and generation controls stay intact.
6. Acceptance requires a real completed MP4 and journals, then a disconnected relaunch and another generation with cellular and Wi-Fi disabled. Exercise backend outage, invalid configuration, interrupted model update and rejected diagnostics. Reproducible measurements, rather than a successful Cloud build, determine inference readiness.

Nothing in this design introduces hosted inference, GPU services, automatic paid upgrades, or an internet dependency after model installation. Backend and model-hosting availability must never be a condition for using a compatible installed model.
